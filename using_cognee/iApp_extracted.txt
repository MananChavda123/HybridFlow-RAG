Employee
‘Employee’ is a commonly used term within every module of the iApp software solution. User performs actions like ‘Add’, ‘Edit’ & ‘Delete’ from a single form. Every piece
of information about the employee is stored and can be fetched whenever needed.
User can configure every form available in module depending upon the requirements, starting from Field Type, Field name, Caption, whether mandatory or not, Field
Size, Field Validation etc. Fresh implementation of iApp contains below tabs. Consider fields stating "*" as mandatory.
Explanation of various buttons used on this screen are as below,
For adding new joiners’ details into iApp
User needs to select Employee (from the list) and then enter resign & relieve date. Also mention reason for resignation; finally click on
SAVE button to take its effect.
Difference between the Resign & the Relieve date is as below,
Resign Date: Date on which employee starts serving his/her notice period as per the company policy
Relieve Date: Date on which employee access to be revoked from all devices. The default out time on the date of relieving would be
23:59 which is editable, or the user can mention the relieving time depending upon the shift assigned to the employee.
User will be able to rejoin a resigned employee. In this case, employee code of the resigned employee will remain same and all
information related to employee can be fetched from the iApp records and need not to be re-entered into the software.
User can simply click on Rejoin button, enter old employee code, mention the reason and tag the ex-employee as the new recruit

Device Management
Devices
This function holds the details of every access control device controller installed in the organization.
Fields details are as below
Location
Location where the controller is to be installed
Device Type
Device Type should be selected as “Controller” or “Reader”.
Controller gets the input from the Reader to assign access whereas Reader passes its input to the controller for
further processing.
Controller Code
Auto Generated & editable field, which can be assigned to the controllers for easy identification.
Controller Type
Type of the controller


--- Page 23 ---
23 / 424
Basically SPECTRA Controllers are divided into two part I.e 2C Family & 3S Family.
Controller Name
Name of the controller for easy identification
Server IP Address
Server IP address where the Controller will PUSH the transactions
Device IP Address
Controller IP (a Unique IP address available in user’s network range)
MAC Address
MAC address to identify each device on a network
Port No.
A number to identify a process that arrives at a server
Communication Mode
Select from:
Ethernet : Used for connecting wired local area networks (LANs), devices communicate with each other through a
protocol(predefined)
GPRS : General Packet Radio Services (GPRS) is a packet-based wireless communication service
Wi-Fi : A wireless networking technology
Device Mode
4 modes available
IN – In this mode all the transactions made would be treated as IN Only.
Out – In this mode all the transactions made would be treated as OUT Only.
Toggle - A user needs to select IN or OUT mode before performing any transaction
NULL – In this mode, a punch can be treated as IN or Out as required.

Authentication
A two-step verification / dual factor authentication, is a security process, offered

Any 2 Users having the access of the door have to authenticate themselves

Interlocking
Interlocking allows the user to configure Gate Inter Locking i.e. if one gates from

group can be open, irrespective of their (locked/unlocked) status.
If all other gates are locked, only then an employee will be given the gate access.
Note: Minimum 2 Gates must be Selected for Gate Interlocking. Controllers that
are already been used for making the interlocking group will not be available
while creating another interlocking group.

Back

Exception is a concept, which is not included in general explanation but still makes a difference to the meaning. But, here in the Access control, when a
user/employee is exempted from any organizational rule, he/she is called to be using an exception.
A user can view the history of the exceptions and even add a new exception record.
There are various types of exceptions available,
For 2C devices
Bypass Local Antipassback
Bypass local Antipassback rule for some selected employees on some selected Doors
Bypass Global Antipassback
Bypass Global Antipassback rule for some selected employees on some selected Doors
Reset Antipassback
Reset Antipassback rule for some selected employee on some selected Doors
Block Access
Block access of an Employee for given time duration on specific Door
Allow Access
Employee is Allowed access for specific time duration on specific Door
Access Mode
Change Access mode (Card Only, card + Finger , card + Pin, Card + Pin + Finger + Finger Only ) of controller for specific time
duration, provision is provided to either select Everyday or specific day (Sun, Mon, Tue…….…Sat)
Door Status
To Change the Door Status(Armed, Open, Close) of Controller for a specific time duration
Armed: On setting the Gate Status ‘Armed’, all the verifications of the card holder will be done at the gate. If it seems to be
unauthorized access, the gate will not open.

Card Format
It is a format into which a card is defined by the data pattern compatible with the SPECTRA Controller.
Below mentioned are the parameters of a Card Format.
Reader Interface
Reader Interface is a mandatory field else the controller will malfunction. It can be either into the Clock interface or into the Wiegand
interface.
Clock
: SPECTRA’s default interface that reads a 26 bit card.
Wiegand
: Standard interface, recognised across the wold.
The original Wiegand interface one parity bit, 8 bits of facility code, 16 bits of ID code, and a trailing parity bit for a total of 26 bits. The
first parity bit is calculated from the first 12 bits of the code and the trailing parity bit from the last 12 bits. However, many
inconsistent implementations and extensions of the basic format still exist.
Site Code
When the selected reader is "Wiegand" and number of Wiegand bits are "26", site code will be asked, which should be changed after a
successful installation, else the controller and application will not function well.
Card Format
Two type of card format i.e. Decimal or Hex
Wiegand Bits
Configure the Wiegand Bits on the Controller or a reader. Its ‘Start’ bit can be set through the use of "Number of Start bits"
Site Code
Set the site code length, which can also be customized.

Stop Bits

Card Format
It is a format into which a card is defined by the data pattern compatible with the SPECTRA Controller. Below are the parameters,
Reader Interface
Reader Interface is mandatory to select and must be according to the requirements of RFID Reader connected to the Controller. It
would be either a Clock Data or a Wiegand
Clock
: SPECTRA default interface of reading 26 bit card.
Wiegand
: Standard interact recognition word wide.
The original Wiegand format has one parity bit, facility code of 8 bits, ID code of 16 bits, and a trailing parity bit for a total of 26 bits.
The first parity bit is calculated from the first 12 bits of the code and the trailing parity bit from the last 12 bits. However, inconsistent
implementations and extensions to the basic format may exist.
Site Code
This option will be available when you have selected the reader type as "Wiegand" and the Wiegand bits are "26".This should not be
changed after a successful installation, as the controller and application would malfunction. This is only a one-time setting done into
the controller.
Card Format
Two type of card format is supported i.e. Decimal and Hex
Wiegand Bits
It will configure the Wiegand Bits on a Controller or a reader. The Start bit can be set through "Number of Start bits" parameter
Site Code
It sets the site code length and unlike Spectra Format its Range could be customized. This is a one-time setting. Its range can be set via
use of the Starting and End Bits of a Site code
Card Number
It configures the Range of Card Number. The start bit can be set through the use of the "Start bits and End Bits"
Stop Bits
Provide the end digits up to which the card bits can be configured
Reader type
Depends upon the RFID Reader connected to the Controller to avoid a malfunction. Available reader types are EMReader, HID Reader,
HID IClasss, Mifare Reverse, Mifare Forward, etc.

Card Format
It is a format into which a card is defined by the data pattern compatible with the SPECTRA Controller. Below are the parameters of the ‘card format’.
Reader Interface
Reader Interface is mandatory to select and must be according to the requirements of RFID Reader connected to the Controller. It would be either
a Clock Data or a Wiegand
Clock
: SPECTRA default interface of reading 26 bit card.
Wiegand
: Standard interact recognition word wide.
The original Wiegand format has one parity bit, facility code of 8 bits, ID code of 16 bits, and a trailing parity bit for a total of 26 bits. The first parity
bit is calculated from the first 12 bits of the code and the trailing parity bit from the last 12 bits. However, inconsistent implementations and
extensions to the basic format may exist.
Site Code
This option will be available when you have selected the reader type as "Wiegand" and the Wiegand bits are "26".This should not be changed after
a successful installation, as the controller and application would malfunction. This is only a one-time setting done into the controller.
Card Format
Two type of card format is supported i.e. Decimal and Hex
Wiegand Bits
It will configure the Wiegand Bits on a Controller or a reader. The Start bit can be set through "Number of Start bits" parameter
Site Code
It sets the site code length and unlike Spectra Format its Range could be customized. This is a one-time setting. Its range can be set via use of the
Starting and End Bits of a Site code
Card Number
It configures the Range of Card Number. The start bit can be set through the use of the "Start bits and End Bits"
Stop Bits
Provide the end digits up to which the card bits can be configured
Reader type
Depends upon the RFID Reader connected to the Controller to avoid a malfunction. Available reader types are EMReader, HID Reader, HID IClasss,
Mifare Reverse, Mifare Forward, etc.
